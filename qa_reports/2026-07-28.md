### 問題 2：國營台鐵推播漏網 — 新竹縣案件被誤判為雙北

- **現象**：07-28 推播的 2 筆中，1 筆為「【臺北營業分處】【土地出租】【新竹縣新豐鄉明新段111、113地號部分土地】」，實際座落**新竹縣**，非雙北地區，不符合業務目標。
- **定位**：`scraper.py:796` `passes_filters()` 對 `title + agency` 做關鍵字比對；`GLOBAL_FILTER["regions"]` 含 `"臺北"`。`parse_tra()`（`scraper.py:194-196`）只用「臺北營業分處」這個**管理單位名稱**做篩選，但臺北營業分處轄區橫跨全台（含新竹）。因為標題本身固定帶有「【臺北營業分處】」字樣，其中的「臺北」二字讓 region 篩選誤判為雙北案件而放行 —— 這是「比對機關名」而非「比對不動產座落地」造成的系統性漏洞。國營台鐵是唯一一個 30 天內 new→notify 轉換率達 100%（11/11）的來源，代表這層防護目前形同虛設。
- **建議修法**：在 `parse_tra()` 內對標題新增地點二次篩選，排除已知非雙北地名：

```diff
--- a/scraper.py
+++ b/scraper.py
@@ -193,6 +193,9 @@ def parse_tra() -> list[dict]:
     # 只保留臺北營業分處的標案
     items = [i for i in items if "臺北營業分處" in i.get("agency", "") + i.get("title", "")]
+    # 臺北營業分處轄區橫跨全台，僅靠單位名無法排除外縣市案件，需再依標題地名二次篩選
+    NON_TAIPEI_HINTS = ["新竹", "桃園", "苗栗", "台中", "臺中", "彰化", "宜蘭", "花蓮", "台東", "臺東"]
+    items = [i for i in items if not any(h in i["title"] for h in NON_TAIPEI_HINTS)]
     log.info(f"  [國營台鐵] {len(items)} 筆（臺北營業分處）")
     return items
```

- **是否已修**：未修（依規則不自動修改程式碼）。待人工套用後，請以下列指令驗證，確認新竹案件被排除、樹林車站案件仍保留：
  ```
  python dry_run_all_regions.py --debug --source 國營台鐵
  ```

### 問題 3：Google Alerts 混入房產媒體新聞報導（非個案公告）

- **現象**：07-26 推播「租期最長20年！國有房地標租續租新制上路台北星鑽20戶7月底打頭陣 - 樂屋網房產新聞」，這是媒體對政策的報導文章，不是具體招標/標租公告案件。
- **定位**：Google Alerts 來源（`scraper.py:786-791`）目前僅以標題關鍵字白名單 + `regions` 含 `"gov.tw"` 放行全台政府公告，未排除房產新聞媒體網域。Google Alerts 30 天內 fetch 81 筆 new，僅 15 筆通過 notify（18.5%），噪音本來就偏高，此為其中一種漏網噪音類型。
- **建議修法**：於 Google Alerts 專屬設定加入媒體關鍵字/網域黑名單（`scraper.py` 約行 786-791 附近 SOURCES 中該來源的 `blacklist`）：

```diff
     {
         "name": "Google Alerts",
         ...
-        "whitelist": ["標租", "出租", "租賃", "招租", "標售", "不動產", "房地", "招商"],
-        "blacklist": [],
+        "whitelist": ["標租", "出租", "租賃", "招租", "標售", "不動產", "房地", "招商"],
+        "blacklist": ["樂屋網", "591", "好房網", "蘋果地產", "新制上路", "房產新聞"],
         "regions":   ["台北", "臺北", "新北", "gov.tw"],
     },
```

  更穩健的做法是改用 URL 網域白名單（僅放行 `.gov.tw` / `.org.tw` 等官方網域，其餘一律視為媒體報導丟棄），但改動範圍較大，建議列入下一輪重構評估。
- **是否已修**：未修，待人工確認關鍵字清單後套用。

## 三、優化建議

### 建議 1：土地銀行出租不動產 — 30 天 12 筆新案件、0 筆推播，通過率 0%，疑似地區篩選誤殺

- **依據**：30 天累計 fetched 均值 2.0 筆/天、`new` 累計 12 筆、`notify` 累計 **0** 筆（通過率 0%）。相對地，國營台鐵同期 `new`=11、`notify`=11（通過率 100%）。土地銀行是全國性公股行庫，其「房地產出租」清單頁對雙北物件的標題/欄位可能只寫門牌地址（如「台北市OO區OO路」的簡寫或分行代號），未必包含「台北」「臺北」「新北」等 region 關鍵字全稱，導致每次都被 `GLOBAL_FILTER["regions"]` 擋下。
- **做法**：先用 `python dry_run_all_regions.py --non-taipei --source 土地銀行出租不動產` 取出最近被地區篩掉的 12 筆項目原文標題，人工確認是否為雙北物件；若確認是誤殺，可補充分行代號對照表（如「台北分行」「城中分行」「新莊分行」等分行名稱關鍵字）到該來源的 region 判斷邏輯，而非僅比對縣市全稱。
- **預期效果**：修正後預期能追回部分目前被誤殺的雙北案件推播，接近國營台鐵的高通過率水準。

### 建議 2：台北市都發局 — 每日固定抓 ~28 筆，30 天僅 1 筆新增且 0 筆推播，長期零產出

- **依據**：30 天 `avg_fetch=28.1`（每天幾乎固定值，顯示為靜態重複清單），累計 `new`=1、`notify`=0。這是本次監測中 fetched 量最大、但轉換率最低的來源。
- **做法**：先確認唯一那 1 筆 `new` 是被 GLOBAL_FILTER 的哪一層擋下（whitelist / region / date window），若為誤殺同建議 1 处理；若查證後確認該局公告頁確實長期無雙北租賃標案（多為都市更新一般行政公告），建議降級為每週人工抽查、或直接移除，釋出抓取資源。
- **預期效果**：釐清是否為真正的低價值來源，避免每天空跑 28 筆資料卻無產出。

### 建議 3（附帶觀察）：郵局房地產出租／台北自來水處／國家住宅及都市更新中心／教育部學產基金 — 30 天合計 0 筆有效推播

- **依據**：4 來源 30 天 `total_new` 分別為 5／3／1／1 筆，`total_notify` 皆為 **0**。
- **做法**：與建議 1、2 相同流程排查是否為篩選誤殺；若排查後確認非誤殺（該機關本身公告週期長、案件稀少），建議合併為單一「低頻來源」清單，降低監測頻率（如每週而非每日），而非直接移除，避免漏掉真正的個案公告。
