## 二、異常與處理

### 問題 1（升級：由「疑似」提升為「已確認」）：政府採購網 parser 抓到與雙北不動產完全無關的全國性標案，長期懷疑今日首次取得具體證據

- **現象**：`state.json` 中「政府採購網」快取（300 筆，已達上限）近期新增內容經逐筆檢視，混入大量與「雙北公有不動產租賃」完全無關的全國性標案，例如：
  ```
  115學年度臺中市國民中、小學﹝海區﹞學生健康檢查委託專業服務採購
  2026雲林滷肉飯節
  115年FSAE-JAPAN參賽運輸
  114年新竹市市區汽車客運業營運及服務評鑑
  艦艇水線下船體矽基型防污漆修補委商
  臺南市瀝青刨除料暫置場選址評估案
  ```
  這些標題完全不含「出租」「標租」二字，也與臺北/新北無關。`08-25`～`09-01` 多份報告已依 url/date 空白率（94.7%～95.3%）推測「疑似 parser 失效」，但受限於執行環境網路出口封鎖 `web.pcc.gov.tw`，過去始終無法直接看到快取的實際標題內容、只能停留在推測階段。本次改用 `python3 -c "json.load(open('state.json'))['政府採購網']"` 直接檢視本地快取檔案（不需連網），首次取得具體反例，可將此問題由「疑似」升級為「確認」。
  由於這些標題不含任何 `GLOBAL_FILTER["whitelist"]` 關鍵字，目前並未造成誤推播（`notify_sum` 32 天累計仍為 0），但代表：
  1. `_pcc_fetch_keyword()`（`scraper.py:390-455`）的 `tenderName=出租`／`tenderName=標租` 查詢參數，很可能並未被政府電子採購網後端真正套用為篩選條件（否則不會回傳「滷肉飯節」這類完全不相關結果）；
  2. `state.json` 300 筆 dedup 上限被大量無關雜訊佔滿，可能排擠真正雙北租賃案件的長期記憶空間，且無從得知過去是否已有真正雙北租賃標案因表格/日期解析錯誤而漏抓。
- **定位**：`scraper.py:390-455`（`_pcc_fetch_keyword()`，尤其 397-409 行組出的查詢字串 `tenderName=` 參數）、`scraper.py:421-426`（`target_table` 判斷邏輯，尋找含「項次」「功能選項」的 `<table>`，可能誤中頁面上其他結構相同的表格，例如「熱門瀏覽」或「最新公告」通用清單而非真正的關鍵字查詢結果表）。
- **建議修法**（無法連線確認 PCC 實際回應內容，故先提出「防禦性」修法，不依賴猜測確切根因）：

  ```diff
  +    # 防禦：即使表格判斷抓到內容，仍要求標題含關鍵字，避免查詢失效時混入全國無關標案
  +    items = [i for i in items if kw in i.get("title", "")]
  +
      log.info(f"  [政府採購網/{keyword}] {len(items)} 筆")
      return items
  ```
  同時建議在有網路權限的環境人工開啟 `https://web.pcc.gov.tw/prkms/tender/common/basic/readTenderBasic?...tenderName=出租...`，確認：(a) 查詢字串是否真的需要額外的 session/cookie 才能生效（政府電子採購網部分查詢頁需先建立 session 才能篩選，直接 GET 可能退回未篩選的預設頁）；(b) `target_table` 的判斷條件是否仍命中正確表格。
- **驗證阻礙**：本次執行環境對 `web.pcc.gov.tw` 為 `EGRESS_BLOCKED`，無法即時重跑 `dry_run_all_regions.py --debug --source 政府採購網` 驗證。

## 三、優化建議

### 建議 1（方向 A）：套用問題 1、2 的防禦性關鍵字檢查，並儘速安排人工在有網路權限環境核對政府採購網／土地銀行的實際 HTML 結構

- **依據**：政府採購網 32 天 `fetched_sum=69`、土地銀行 32 天 `fetched_sum=60`，`state.json` 快取合計 300+60=360 筆中，經抽查兩來源快取內容 0 筆與雙北不動產租賃相關（政府採購網混入全國性醫療/餐飲/交通標案，土地銀行混入銀行系統維護公告）。`notify_sum` 目前皆為 0，尚未造成誤推播，但長期佔用 `state.json` 300 筆 dedup 上限、且無法排除因表格/日期解析錯誤而漏抓真正雙北租賃標案的風險。
- **做法**：先套用問題 1、2 報告中的防禦性 diff（收窄關鍵字條件），降低雜訊持續累積 dedup 快取的速度；同時安排人工在有網路權限的環境開啟兩站原始頁面，核對 `target_table`／CSS 選擇器是否仍對應正確的查詢結果表格，並用 `dry_run_all_regions.py --debug --source <來源>` 做修正前後筆數對照。
- **預期效果**：兩來源快取內容回歸真正的雙北不動產租賃相關項目，`state.json` dedup 空間不再被無關雜訊佔用，且未來若這兩站真的出現雙北案件時能被正確捕捉，不會被無關雜訊淹沒。

### 建議 2（方向 A，延續）：問題 3、4、6 的 diff 儘速一次套用

- **依據**：問題 3、4、6 三組 diff 互不衝突，且問題 4（國有財產署 `skip_global_filter`）已於 09-01 造成 1 筆真實漏網推播，問題 3（黑名單缺「停車場」「決標結果」「廣告標租」）也已有 3 筆歷史真實外洩案例（08-17、08-20、08-24），非僅理論風險。
- **做法**：一次套用問題 3（黑名單新增關鍵字）、問題 4（移除「停車場」分類頁＋拿掉 `skip_global_filter`）、問題 6（`SOURCES` 逐來源篩選生效）的 diff，並在有網路權限環境用 `dry_run_all_regions.py --debug` 做全來源前後筆數對照。
- **預期效果**：排除已確認的 3 類誤報型態，國有財產署的推播回歸「標題含出租/標租/租賃等關鍵字」才放行。
