### 問題 6（新發現，低優先級）：SOURCES 內個別來源自訂的 whitelist／blacklist／regions 欄位是死代碼

## 三、優化建議

### 建議 1：郵局房地產出租、國家住宅及都市更新中心的低產出並非「案源少」，而是問題 4 的地區篩選缺陷所致 —— 建議優先修 bug 而非降級/移除

- **依據**：問題 4 已用實際數字證明兩來源分別有 82%、71% 的抓取項目因為 `agency` 欄位缺失+標題只寫行政區名而被地區篩選誤殺，且各已找到至少 1～2 筆具體漏網的雙北租賃案件。
- **做法**：套用問題 4 的 diff，而非依照昨日報告「建議 2/3」的方向考慮降級或移除這兩個來源。
- **預期效果**：預估兩來源的 notify 轉換率可從目前的 0% 提升到接近其「無 region 關鍵字」項目中雙北案件的實際佔比（保守估計至少能追回本次已驗證的 3 筆）。

### 建議 2：4 個依賴 Claude fallback 的來源應補上原生 CSS/regex parser，降低對單一 API 供應商的相依性

- **依據**：問題 1 顯示，教育部學產基金／台北市都發局／國防部政治作戰局／政府採購網（出租類）過去 30 天 fetched 數值高度穩定（如台北市都發局恆為 ~28-30 筆），這種穩定性通常代表資料是由**同一套穩定的解析路徑**（Claude fallback）產出，而非每天變動的原生 CSS parser；一旦 Claude API 中斷，這 4 個來源直接歸零，已連續發生 2 天。
- **做法**：逐一檢查這 4 個來源目前的原生 CSS parser 為何長期抓不到資料（可能是網站改版，selector 已失效），修正或重寫 selector，讓 Claude fallback 真正回歸「備援」角色。
- **預期效果**：即使 Anthropic API 再次中斷，這 4 個來源仍能維持基本抓取能力，不會整批歸零。

### 建議 3：土地銀行出租不動產應「修正選擇器」而非「移除」
