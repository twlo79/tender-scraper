## 二、異常與處理

### 問題 1：國營台鐵「臺北營業分處」誤判為雙北地區，造成非雙北物件外洩
- **現象**：`國營台鐵` 來源標題固定以「【臺北營業分處】」開頭（該分處管轄範圍涵蓋新竹、桃園、新北等地，並非只轄雙北）。`passes_filters()` 對地區的檢查是拿 `title + agency` 全文字串比對 `GLOBAL_FILTER["regions"]`，只要標題含「臺北」二字就視為通過，等於地區篩選對此來源永遠失效。
  抽查 state.json 最近 15 筆「國營台鐵」項目，僅 2 筆（新北中和、新北淡水）真的在雙北，其餘 13 筆（87%）分別位於新竹縣竹東鎮、新竹市香山區、新竹縣新豐鄉、桃園市楊梅區等地，全部因「臺北營業分處」字樣通過地區篩選。
  **已確認實際外洩案例**：2026-08-07 推播了「【臺北營業分處】【房地標租】【新竹縣新豐鄉新興路202號房地（新豐舊站）】」——這是新竹縣的物件，不符合雙北租賃標的業務目標，卻被推播給使用者。
- **定位**：`scraper.py:194-196`（`parse_tra()`）只保留分處名稱含「臺北營業分處」的項目，未擷取標題中第 3 個中括號（實際地點）；`scraper.py:796-814`（`passes_filters()`）用整段 `title+agency` 做地區比對，因此永遠命中。
- **建議修法**：在 `parse_tra()` 內從標題擷取第 3 段中括號（實際地點）作為 `region_text`，並讓 `passes_filters()` 優先使用 `region_text` 而非整段標題來判斷地區。

  ```diff
  --- a/scraper.py
  +++ b/scraper.py
  @@ parse_tra()
           a = item.select_one("div.btn-box a[href]")
           href = urljoin(BASE, a["href"]) if a else URL
  -        items.append({"title": title, "date": dt, "url": href, "agency": unit})
  +        # 標題格式：【臺北營業分處】【類別】【實際地點】【日期】
  +        # 分處名稱固定含「臺北」，不能代表物件所在地，需另外擷取第3段地點供地區篩選使用
  +        _parts = re.findall(r"【([^】]*)】", title)
  +        region_text = _parts[2] if len(_parts) >= 3 else title
  +        items.append({"title": title, "date": dt, "url": href, "agency": unit, "region_text": region_text})

  @@ passes_filters()
   def passes_filters(item: dict) -> bool:
       title  = item.get("title", "")
       agency = item.get("agency", "")
  -    text   = title + agency
  +    text   = item.get("region_text", title + agency)
  ```

  此修法只在 item 提供 `region_text` 時改變地區判斷依據，其餘來源沒有設定 `region_text`，行為不受影響，風險低。
- **是否已修**：未修。本環境（沙盒）出網受管制代理限制，無法對 `railway.gov.tw` 發出請求驗證（`dry_run_all_regions.py` 對外部網域皆回傳 `403 Tunnel connection failed`），依規則「若動手改 parser 必須用 dry_run 驗證通過才算完成」，故僅提供 diff，待有網路權限的環境套用並驗證後再套用。

### 問題 2：台北市都發局／國防部政治作戰局 累積項目 url 全為空
- **現象**：`state.json` 中「台北市都發局」（32 筆）與「國防部政治作戰局」（11 筆）的 `url` 欄位 100% 為空字串 `""`。若這兩來源未來有新案觸發推播，LINE flex message 的「前往原始網頁」按鈕會連到空網址，使用者無法點擊查看原文。
- **定位**：
  - `parse_taipei_udd()`（`scraper.py:515`）與 `parse_gpwd()`（`scraper.py:560`）在正常路徑（table 選取器命中）時一定會給 `url` 賦值（前者至少 fallback 到列表頁，後者要求必須有 `<a href>` 才建立項目，不可能是空字串）。
  - 兩來源目前 100% 空 url，強烈指向兩者實際上都是走 `parse_with_claude_fallback()`（`scraper.py:675`）——即目前的 CSS/table 選擇器對即時網頁已經抓不到資料（0 筆），才觸發 Claude 文字回退解析；而回退解析只餵給 Claude 純文字（`soup.get_text()`），文字裡沒有 `href` 屬性，Claude 自然無法還原網址，`item.get("url","")` 因此永遠是空字串。
  - 佐證：`daily_report.json` 中 2026-07-28 的錯誤紀錄「`[台北市都發局] Claude API 錯誤：invalid_request_error — This organization has been disabled.`」「`[國防部政治作戰局] Claude API 錯誤：...`」，顯示這兩個來源當時完全依賴 Claude fallback，一旦 Claude API 不可用就直接掛零——這正是 2026-08-12 QA 報告提到的「15 天 API 停用問題」。
- **建議修法**：需要有網路存取權限的環境（本沙盒對 `udd.gov.taipei`、`gpwd.mnd.gov.tw` 出網被 egress proxy 擋下，無法直接勘查即時 HTML）执行：
  ```bash
  python dry_run_all_regions.py --debug --source "台北市都發局"
  python dry_run_all_regions.py --debug --source "國防部政治作戰局"
  ```
  比對輸出是否為 0 筆走 Claude fallback，並用瀏覽器/curl 檢視 `https://udd.gov.taipei/events/psxwq1j`、`https://gpwd.mnd.gov.tw/Publish.aspx?cnid=609` 目前實際的 table/row 結構，修正 `scraper.py:533`（`soup.select("table tbody tr, table tr")`）與 `scraper.py:573`（`soup.select("table tbody tr, table tr, .listContent tr")`）對應的選擇器，讓正常路徑能命中，恢復可用的個別公告 url。
- **是否已修**：未修，需要能連外的環境才能勘查真實 HTML 結構後修正選擇器。

### 問題 3（附帶發現，非本次異常但建議留意）：SOURCES 內各來源自訂 whitelist/blacklist/regions 為死代碼
- **現象**：`SOURCES`（`scraper.py:703-793`）內每個來源都定義了自己的 `whitelist`/`blacklist`/`regions`（如政府採購網、教育部學產基金、台北市都發局、國防部政治作戰局、土地銀行、Google Alerts），但主流程 `passes_filters(i)`（`scraper.py:1151`）只接收 `item`，函式內只讀取全域的 `GLOBAL_FILTER`，從未讀取這些來源自訂值。目前因為所有來源自訂清單剛好是 `GLOBAL_FILTER` 的子集合，所以尚未造成可觀察的錯誤行為，但屬於容易誤導維運者的死代碼——未來若有人想針對特定來源加嚴或放寬篩選（例如 Google Alerts 的 `regions` 多了 `"gov.tw"` 想放行更多政府網域，實際上完全不會生效），改了也不會生效。
- **定位**：`scraper.py:796`（`passes_filters` 簽章與內容）、`scraper.py:1149-1152`（呼叫處）。
- **建議修法**：屬設計決策，列入待決事項，不在本次自動處理。

## 三、優化建議

### 建議 1：修正國營台鐵地區判斷邏輯（見問題 1）
- **依據**：近 15 筆存量中 13 筆（87%）非雙北物件通過地區篩選，且已造成 1 次實際錯誤推播（2026-08-07 新竹縣新豐鄉物件）。
- **做法**：採用問題 1 提供的 diff，改用標題第 3 段中括號（實際地點）做地區判斷。
- **預期效果**：國營台鐵來源的地區篩選由「恆通過」變成「依實際物件地點篩選」，預估未來僅約 13% 的項目（雙北者）會通過，其餘 87% 的新竹/桃園物件將被正確排除，避免再次誤推。

### 建議 2：修復都發局／政治作戰局 parser 選擇器，脫離 Claude fallback 依賴（見問題 2）
- **依據**：兩來源合計 43 筆存量 100% 缺失 url；且 2026-07-28 log 證實這兩來源曾因 Claude API 停用而完全抓不到資料（fallback 完全失效時直接歸零），顯示目前架構對外部 LLM API 的可用性有不必要的依賴。
- **做法**：在有網路權限的環境重新勘查兩網站的即時 HTML table 結構，修正 CSS 選擇器，讓主要爬取路徑（非 Claude fallback）能正常命中，順便恢復可用的個別公告網址。
- **預期效果**：兩來源恢復用穩定的 table 選擇器抓取，不再受 Claude API 額度/停用影響；未來若有新案推播，使用者可正常點擊查看原文連結。
