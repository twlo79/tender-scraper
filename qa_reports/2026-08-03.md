- **現象**：`SOURCES`（`scraper.py:703-793`）每個來源字典都定義了 `whitelist`/`blacklist`/`regions`（如政府採購網、教育部學產基金、Google Alerts 等），註解也寫明設計意圖（例如 Google Alerts 的 `regions` 特別加了 `"gov.tw"` 想放行「全台政府公告」）。但 `passes_filters(item)` 函式簽名只吃 `item` 一個參數（`scraper.py:796`），內部只讀取全域 `GLOBAL_FILTER`，完全沒有讀取 `src["whitelist"]` 等欄位——全文搜尋 `["whitelist"]`／`.get("whitelist"` 等只在 `GLOBAL_FILTER` 出現過。這代表 Google Alerts 想放行「標題無雙北字樣但網域為 gov.tw」的政府公告這個設計意圖**從未真正生效**。

  ```python
  def passes_filters(item: dict, src: dict | None = None) -> bool:

      agency = item.get("agency", "")
      text   = title + agency

      regions   = (src or {}).get("regions")   or GLOBAL_FILTER.get("regions", [])
      whitelist = (src or {}).get("whitelist") or GLOBAL_FILTER.get("whitelist", [])
      blacklist = list(GLOBAL_FILTER.get("blacklist", [])) + list((src or {}).get("blacklist", []))

  ```

## 三、優化建議

### 方向 A：篩選精準度

**建議 1（最高優先）：先解決問題 1，並補強 3 個 Claude-only 來源的原生 parser 容錯**

- 預期效果：Claude API 未來若再中斷，不會讓 3 個來源同時斷線超過 1 天。

**建議 2：修問題 2（台鐵地區篩選漏洞）——已有 2 次實際外洩紀錄**

### 方向 B：來源健康度

**建議 3：31 天 sent_log 掃描顯示多個來源長期 0 推播，但成因需分辨「無新案」與「篩選過嚴」**

- 依據（實際數字，31 天窗口）：台北自來水處、郵局房地產出租、國家住宅及都市更新中心、土地銀行出租不動產 — 這 4 個來源在整個 31 天 sent_log 中 `notify` 皆為 0 次；瑠公管理處、台北市財政局也僅各 1 次。但程式邏輯上「新增」判定（`find_new_items`）是先做，篩選（`passes_filters`）後做（`scraper.py:1146-1152`），代表這些來源 fetched 數字穩定不變、new 也持續是 0，**多半反映該政府網站本身很少更新列表**，而非白名單擋掉了新案件——因為連「new」都沒有，篩選根本沒機會發生作用。

- 預期效果：避免誤刪掉「平時安靜、但仍會有價值案件」的來源，同時建立未來判斷移除的量化門檻。
