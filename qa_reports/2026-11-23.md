## 二、異常與處理
### 問題 1：政府採購網連續 4 天 HTTP 500（延續，越來越急）
- 現象：11/19–11/22 每天都是 0 筆，錯誤一樣是 `readArpam?searchAssetsName=出租|標租&searchBeginNoticeDate=...&pageModel.rowsPerPage=100` 回 500
- 定位：連續 4 天、兩個關鍵字都失敗，幾乎可以確定是 PCC 改了端點或參數，不是暫時故障。`scraper.py:466` 已經有 `_arpam_debug()`，會依序試 7 種參數組合（拿掉 rowsPerPage、改民國年、rowsPerPage=10 等），**但只在 DRY_RUN 執行**。daily.yml #183–#187 都是 `DRY_RUN: false`，所以這段診斷從來沒有在 Actions 環境跑過

  1. **用 dry run 手動跑一次 workflow**（GitHub → Actions → 每日標案爬蟲 → Run workflow → 勾選 `dry_run`）。這樣不會推播，也不會寫 state/sent_log。跑完看 log 中的 `[PCC DEBUG]` 段落，就知道哪個參數組合能用

  3. 在 `_arpam_fetch_keyword()` 加重試，或讓 `_arpam_debug` 在正式 run 第一次失敗時也執行（只印 log，不影響推播）：
     ```diff
     @@ scraper.py _arpam_fetch_keyword 例外處理處
     -        if DRY_RUN:
     -            _arpam_debug(keyword, start, end)
     +        _arpam_debug(keyword, start, end)   # 每次 run 只會跑一次，只印 log
     ```
     （實際條件寫法以 511–587 行為準）
- **時限**：日期窗是 10 天。11/19 起漏掉的案件，要在 **11/29 前**修好才補得回來，現在剩 6 天
